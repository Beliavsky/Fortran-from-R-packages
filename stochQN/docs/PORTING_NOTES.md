# Porting notes

## Directly translated numerical algorithms

The following numerical components were translated from `src/stochqn.c`:

- circular limited-memory storage for BFGS correction pairs
- L-BFGS two-loop inverse-Hessian product
- optional scalar, diagonal AdaGrad, or diagonal RMSProp initialization
- online L-BFGS same-batch gradient differences
- SQN averaged-iterate correction pairs
- SQN Hessian-vector and large-batch gradient-difference modes
- adaQN empirical-Fisher correction pairs
- adaQN large-batch gradient-difference mode
- adaQN validation-loss rollback
- curvature filtering, `y` regularization, memory flushing, and finite-direction checks
- the original reverse-communication task and status state machines

## Intentional robustness corrections

The following changes correct unsafe or apparently incomplete behavior in the
supplied package source. They are documented rather than hidden.

1. **Zero correction-memory sizes are rejected.** The R validation accepted
   `mem_size = 0`, but the C kernel subsequently performed modulo operations by
   the memory size.

2. **Nonpositive or numerically singular curvature pairs are rejected.** With a
   zero user curvature threshold, the C code could retain `s'y <= 0` or divide
   by zero in the two-loop recursion. The Fortran port always requires a small
   positive curvature ratio.

3. **adaQN gradient-difference mode advances the previous averaged iterate.**
   The supplied C SQN path copied the accepted current average to the previous
   average, but the analogous adaQN path copied only the gradient. Omitting the
   average causes later `s` vectors to span multiple update intervals.

4. **adaQN validation rollback clears the accumulated iterate sum.** The C path
   reverted `x` and flushed memories but retained an already averaged `x_sum`,
   which contaminated the next averaging interval.

5. **The typed logistic wrapper completes an oLBFGS same-batch request before
   returning from `partial_fit`.** This guarantees that the second gradient is
   evaluated on the same batch, rather than accidentally using the next batch.

## Fortran-specific design

- Arrays and allocatable components replace manual `malloc`/`free` ownership.
- Circular-memory indices are one based.
- Optimizer inputs are checked before state transitions.
- The number-of-threads argument is omitted because this self-contained port
  uses standard Fortran intrinsics and does not control a vendor BLAS runtime.
- Callback interfaces use optional unlimited-polymorphic user data.
- The high-level runners stop only after completing any pending correction-pair
  request generated by the final parameter update.

## Omitted R infrastructure

- S3 classes and print/summary methods
- formulas, factors, data frames, and `model.matrix`
- R environments and reference-semantics mutation
- R random-number initialization and parallel core detection

These are interface facilities rather than numerical algorithms.
