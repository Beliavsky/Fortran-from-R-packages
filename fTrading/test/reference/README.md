# Genuine R regression fixtures

`fixtures.txt` was generated by the **unmodified installed fTrading 3042.79**
package. It supplies 118 numerical comparisons covering all 40 documented
computational exports and the four additional exported dot-prefixed helpers.
The helper `.dailyTA` is exercised through all 19 selector branches and an
explicit alternative input column. The default Fortran tests need neither R
nor an installed R package: they read this checked-in data file.

## Regeneration

From the `fTrading` package root, with fTrading 3042.79 and its R dependencies
installed, run:

```sh
Rscript test/reference/generate.R
fpm test --target test_r_fixtures
```

The script loads the genuine package, sources the three bundled upstream
computational R files into a separate environment, and verifies identical
formal arguments and parsed function bodies for **all 45 upstream functions**,
including the excluded plotting function. It then calls only the installed
package functions for the numerical oracle. No functions are repaired,
reimplemented, or stubbed. No RNG is involved. Dependency versions and known
original errors are recorded in `provenance.txt`; `coverage.tsv` lists the
covered computational entry points.

The 96-observation deterministic OHLCV sample has upward and downward price
changes, equal consecutive closes, upward and downward volume changes, and
equal consecutive volumes. Input values are also stored, so the Fortran test
uses precisely the floating-point values passed to R rather than regenerating
trigonometric expressions in another language. Matrices are serialized in
column-major order.

## Cases that deliberately preserve upstream behavior

- Default and custom parameters cover every parameterized indicator.
- Custom `cdoTA` periods retain its default-period signal-line calculation.
- `garmanklassTA` uses raw-price intraday differences and only logs its
  overnight return. It is not replaced by a conventional logarithmic formula.
- The middle column of `bollingerTA` is the original input series.
- `fpkTA` and `wprTA` use expanding startup windows and `lag + 1` observations
  thereafter. RSI follows the corresponding lagged-change convention.
- `nviTA` and `pviTA` use the current close as the return denominator and divide
  that fraction by 100.
- EMA checks include zero decay, a period of one, a nonintegral decay, a period
  greater than one, an explicit startup, an oversized startup, and a series
  shorter than the default startup. EWMA covers automatic and explicit seeds.
- Rolling checks cover all six named reductions, a custom pure callback,
  padded and trimmed outputs, window-local missing values, globally removed
  missing values, width one, and population versus sample variance.
- Benchmark checks include scalar and varying risk-free returns, custom scales,
  an undersized Sharpe input, infinite Sterling ratio, and all tied peak/trough
  indices for repeated maximum drawdowns.
- Trading helpers check signal values and indices, timestamp differences in
  days, zero-return half-hits, and omitted missing observations.

## Original vector-interface defects

`chaikinvTA(high, low)` fails because its numeric-vector path never assigns
`rt`; it resolves instead to the unrelated `stats::rt` function.
`williamsadTA` and `williamsrTA` refer to an undefined `x` when assigning names
on their vector paths. The generation script asserts that these three original
errors still occur. Their successful **original timeSeries paths** supply the
fixtures, after extracting numeric values. This verifies the underlying
computations without claiming that the broken R vector interfaces work.

## File format and comparison

The first line is the record count. Each record consists of its unique label,
its scalar count, and one scalar per line. Finite values use 17 digits after the
decimal point; NA and NaN both use `NaN`, and signed infinities retain their
sign. The current data has 131 records and 10,366 scalars, including inputs.

The Fortran test verifies shape, matches missing values separately with
`ieee_is_nan`, checks infinity signs, and compares finite values with
`3e-11 * max(1, abs(reference))` tolerance. Every record must be consumed.

These fixtures establish the listed numerical behavior on deterministic input;
they do not test R object construction, metadata, warnings, recycling, plotting,
or every possible input. They supplement the package's invariant and edge-case
tests rather than asserting full R-interface compatibility.
