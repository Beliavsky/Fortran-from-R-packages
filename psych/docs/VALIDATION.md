# Validation

Validation was performed in the translation sandbox with GNU Fortran 14.2.0.

## Dependency-interface validation

The starting translation already depends on the repository sibling packages `rfortran-core` and `rfortran-linalg`. The translated package continues to import `dp` from `r_kinds` and uses only the high-level `rfortran-linalg` operations needed by the mapped scope; no new external numerical dependency was introduced. For direct compiler validation in this sandbox, small interface-compatible validation stubs for those public calls were kept **outside** the deliverable package; they are not present in `psych.zip`.

The upstream `glb.algebraic` routine delegates a semidefinite program to Rcsdp. No compatible shared Rcsdp/SDP translation was identified in the repository audit, so this package translates that specific bounded minimum-trace SDP with an in-package ADMM algorithm. The split alternates an exact fixed-off-diagonal/bounded-diagonal proximal step with positive-semidefinite eigenvalue projection through `rfortran-linalg`. Analytic equicorrelation, zero-correlation, scaling, and unequal-variance boundary cases are included in deterministic tests.

The upstream `omegaSem` routine delegates confirmatory factor analysis to lavaan. The translated numerical path implements the specific orthogonal standardized bifactor CFA generated by `omega.sem`: Schmid-Leiman loadings define the item-to-group-factor zero pattern, normal-theory maximum likelihood is minimized with analytic gradients and BFGS/Armijo updates, SPD inverse/log-determinant work is routed through `rfortran-linalg`, and the fitted loadings are passed to the existing `omegaFromSem` calculations. Deterministic tests cover exact one-factor and two-group bifactor covariance structures, including fit discrepancy, uniquenesses, omega statistics, and chi-square scaling. Generic lavaan syntax, fit objects, and arbitrary SEM models remain outside the translated interface.

## Checked build

All maintained package sources were compiled with the equivalent of:

```text
gfortran -std=f2018 -Wall -Wextra -Werror -Wimplicit-interface -fcheck=all -fbacktrace
```

The dependency-interface stubs were compiled separately and were not subjected to the package's 132-column source audit. The package sources themselves compile without `-ffree-line-length-none`.

## Optimized build

A separate build used:

```text
gfortran -std=f2018 -O2 -Wall -Wextra -Werror -Wimplicit-interface
```

All five test programs and the example passed again. The optimized validation shell was split into two commands after the first command hit the sandbox execution-time limit; the compiled sources and all subsequently run tests passed. No fast-math, finite-math-only, or equivalent unsafe IEEE assumptions were used.

## FPM commands

The required literal commands were attempted from the package root:

```text
fpm build
fpm test
fpm run --example basic
fpm clean --all
```

All four returned exit status 127 because this sandbox does not contain an `fpm` executable (`fpm: not found`). Network access from the command-line environment is also unavailable, so FPM could not be installed during validation. These commands are therefore **not** reported as successful FPM runs.

## Static release audit

The release audit checks:

- translation metadata consistency (344 mappings, 344-function computational denominator, no untranslated names);
- all 39 maintained Fortran source/test/example files are ASCII free-form files (33 under `src/`, five tests, and one example);
- every mapped R source path and Fortran implementation source;
- every mapped Fortran procedure exists and is public in its declared module;
- each dummy argument is declared separately with explicit `INTENT` or `VALUE` and a trailing `!!` FORD comment;
- maximum maintained-source line length of 132 columns;
- no semicolon-separated code statements except the explicitly permitted simple `SELECT CASE` form;
- no `double precision`, `real*8`, D-exponent literals, or local duplicate definition of `dp`;
- no self-comparison NaN idioms;
- no `-ffast-math`, `-Ofast`, `-ffinite-math-only`, system BLAS/LAPACK links, or vendored numerical dependencies;
- no duplicate maintained Fortran source files; and
- no object, module, executable, cache, or nested ZIP artifacts in the deliverable tree.

The final working-tree audit completed with zero findings before packaging.
